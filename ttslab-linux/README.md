# TTS Lab для Linux — подбор голоса для озвучки в локальной сети

Панель, которая ставит 10 моделей озвучки, поднимает **одну выбранную** как OpenAI-совместимый API в локальной сети и даёт страницу, где можно вставить текст, послушать, поменять настройки и оценить результат. Без LiteLLM: клиенты в сети ходят в сервер напрямую.

## Быстрый старт

```bash
cd ~/ttslab-linux
./install.sh            # меню: выбрать модели (или ./install.sh all)
./start.sh              # панель в фоне
```

- `http://<IP-сервера>:8800/admin` — выбрать модель и нажать «Запустить», смотреть логи и загрузку видеокарты.
- `http://<IP-сервера>:8800/` — страница теста: текст, настройки, прослушивание, оценки.

Остановить: `./stop.sh` (всё) или `./stop.sh model` (только модель). Статус: `./status.sh`.
Автозапуск через systemd: `./service.sh install` (поднимет панель и модель, которая работала последней). Чтобы работало без входа в систему: `sudo loginctl enable-linger $USER`.

## Требования

- Ubuntu/Debian (на других дистрибутивах поставьте вручную: ffmpeg, git, sox, lsof, portaudio, libsndfile).
- Видеокарта NVIDIA с драйвером — желательно. Установщик сам определит её и поставит torch с CUDA; без неё — CPU-сборку (`TORCH_BACKEND=cpu ./install.sh` — принудительно).
- Без видеокарты быстро работает только Silero; остальные — от десятков секунд до минут на фразу.

| 10 | XTTS-v2 | ~4 ГБ | некоммерческая |
| — | Тест: синус | не нужна | проверка связи без нейросети |

Higgs Audio V3 из Mac-версии здесь нет: на Linux он запускается только через SGLang-Omni на большой видеокарте, а на русском показывал худший результат из всех.

Каждая группа живёт в своём `venvs/<группа>` (разные версии torch/transformers). Fish S2 Pro ставится из исходников в `vendor/fish-speech`, его веса — в `models/fish/`. Остальные веса — в `~/.cache/huggingface`.

ESpeech и F5 без голоса-образца не говорят: при установке Silero создаёт `refs/default_female` и `refs/default_male`. Свои образцы (5–12 секунд + точная расшифровка) загружаются в /admin.

## Подключение из других программ

API совместим с OpenAI. Адрес, ключ и примеры показаны в /admin.

```bash
curl http://<IP-сервера>:8890/v1/audio/speech -H "Content-Type: application/json" \
  -d '{"input":"Записываю вас на 17:00, врач Дорохов С. А.","voice":"alloy","response_format":"wav"}' -o test.wav
```

```python
from openai import OpenAI
client = OpenAI(base_url="http://<IP-сервера>:8890/v1", api_key="none")
with client.audio.speech.with_streaming_response.create(
    model="local-tts", voice="alloy", input="Записываю вас на 17:00", response_format="wav",
    extra_body={"settings": {"initials": "drop"}},
) as r:
    r.stream_to_file("test.wav")
```

Адрес не меняется при переключении модели. Ключ по умолчанию не нужен; чтобы закрыть API, задайте `TTS_API_KEY` в `config.env`.

### Как настройки доходят до модели

1. Поле `settings` в теле запроса (или любые ключи настроек на верхнем уровне).
2. Поле `instructions` с текстом `ttslab:{...json...}`.
3. Запросы без настроек получают значения, сохранённые кнопкой «Сохранить для API» на странице теста.
4. `voice`: имя голоса модели (например `kseniya` для Silero) или `ref:<имя образца>`; стандартные голоса OpenAI (`alloy` и т. п.) означают «голос из настроек».

## Нули и инициалы

Перед любой моделью текст проходит нормализацию (`server/normalizer.py`), её видно на странице теста в блоке «Что прочитает модель»:

- `17:00` → «семнадцать ноль ноль» (или «семнадцать часов» — переключается);
- `Дорохов С. А.` → «Дорохов эс а», «Дорохов» или как есть;
- даты, телефоны, суммы, сокращения → слова (ru-normalizr);
- свой словарь произношений — в /admin, применяется сразу.

## Скорость ответа

Страница `http://<адрес>:8800/bench` (вкладка «Скорость») или `./bench.sh` в терминале.

Модели запускаются по очереди (на сервере всегда одна), для каждой меряется:

- **Загрузка** — от команды запуска до готовности: веса + прогрев. Если весов нет, сюда входит скачивание.
- **Первый запрос** — первый ответ сразу после загрузки.
- **Ответ на короткие / средние / длинные фразы** — медиана и p90 полного времени от отправки запроса до получения всего аудио.
- **RTF** — время работы нейросети ÷ длительность аудио; меньше 1 — быстрее реального времени.
- **Символов в секунду** и **накладные** — всё, что не нейросеть: нормализация текста, очередь, кодирование, сеть.
- **Память** — пик ОЗУ и памяти ускорителя (CUDA).

Запросы идут прямо в API модели с сохранёнными «настройками для API», то есть так же, как у боевых клиентов. Результаты хранятся в `data/bench/`, выгружаются в CSV, по завершении возвращается модель, работавшая до замера.

```bash
./bench.sh                                   # все установленные модели
./bench.sh silero-v5 omnivoice               # выбранные
SETS=short,medium,long REPEATS=5 ./bench.sh  # все длины фраз, 5 повторов
```

В каждом ответе API есть разбивка времени: заголовок `X-Timing` (нормализация, очередь, нейросеть, первый кусок, кодирование) и `X-Server-Time`. На странице теста она видна при наведении на «синтез» у дубля.

## Логи

- `logs/worker.log` — модель: загрузка, каждый кусок текста, время синтеза.
- `logs/requests.jsonl` — каждый запрос: текст, что прочитано, настройки, RTF, ошибки.
- `logs/worker.out` — сырой вывод процесса (трейсбеки, прогресс скачивания).
- `logs/install.log`, `logs/panel.log`; при работе через systemd ещё `./service.sh logs`.

## Настройки в config.env

`PANEL_PORT`, `TTS_PORT`, `TTS_API_KEY`, `MODEL_ALIAS`, `PANEL_PASSWORD` (пароль на панель), `AUTOSTART_LAST`. После изменения: `./stop.sh && ./start.sh` (или `systemctl --user restart ttslab`).

## Если что-то не так

- **Модель в статусе «ошибка»** — /admin → Логи → «Модель» или «Вывод процесса».
- **CUDA out of memory** — модель не помещается в видеокарту: выберите устройство `cpu` или точность `float16` в параметрах загрузки.
- **«Порт занят»** — кнопка «Освободить порт» в /admin или `ss -ltnp 'sport = :8890'`.
- **Другие компьютеры не открывают страницу** — откройте порты: `sudo ufw allow 8800,8890/tcp`.
- **Окружение не поставилось** — `./install.sh <id модели>` ещё раз, ошибка в `logs/install.log`.
