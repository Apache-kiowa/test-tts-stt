# TTS Lab — подбор голоса для озвучки на Маке

Панель, которая ставит 11 моделей озвучки, поднимает **одну выбранную** как OpenAI-совместимый API для LiteLLM и даёт страницу, где можно вставить текст, послушать, поменять настройки и оценить результат.

## Быстрый старт

```bash
cd ~/ttslab
./install.sh            # меню: выбрать модели (или ./install.sh all)
./start.sh              # панель в фоне
```

- `http://<IP-мака>:8800/admin` — выбрать модель и нажать «Запустить», смотреть логи.
- `http://<IP-мака>:8800/` — страница теста: ключ LiteLLM, текст, настройки, прослушивание, оценки.

Остановить: `./stop.sh` (всё) или `./stop.sh model` (только модель). Статус: `./status.sh`.
Автозапуск после перезагрузки Мака: `./service.sh install` — поднимет панель и модель, которая работала последней.

## Подключение к LiteLLM (один раз)

LiteLLM → Models → Add Model:

| Поле | Значение |
|---|---|
| Provider | OpenAI |
| LiteLLM Model Name | `mac-tts` |
| Model Mappings | `mac-tts` → `mac-tts` |
| Mode | Audio Speech - /audio/speech |
| Upstream API Base | `http://10.16.80.30:8890/v1` (точный адрес показан в /admin) |
| API Key | `lm-studio` |

Порт 8890 и ключ не меняются при смене модели, поэтому LiteLLM трогать больше не нужно: переключили модель в панели — LiteLLM уже ходит в неё. Порты 8000 (Whisper) и 8880 (Джарвис) не заняты.

Проверка:
```bash
curl http://litellm.edu.ingacademy.ru/v1/audio/speech \
  -H "Authorization: Bearer КЛЮЧ_LITELLM" -H "Content-Type: application/json" \
  -d '{"model":"mac-tts","input":"Записываю вас на 17:00, врач Дорохов С. А.","voice":"alloy","response_format":"wav"}' -o test.wav
```

В Wordtrip для этого: `TTS_MODEL=mac-tts`. Поле `voice` можно оставить как есть (`coral` и т. п. — тогда берётся голос из настроек), либо указать голос модели, например `kseniya` для Silero.

## Нули и инициалы

Перед любой моделью текст проходит нормализацию (`server/normalizer.py`), её видно на странице теста в блоке «Что прочитает модель»:

- `17:00` → «семнадцать ноль ноль» (или «семнадцать часов» — переключается);
- `Дорохов С. А.` → «Дорохов эс а», «Дорохов» или как есть;
- даты, телефоны, суммы, сокращения → слова (ru-normalizr);
- свой словарь произношений — в /admin, применяется сразу.

## Как настройки доходят до модели

1. С тестовой страницы — в поле `instructions` в виде `ttslab:{...json...}`: LiteLLM пропускает это поле в Upstream.
2. Запросы без настроек (например, из Wordtrip) получают значения, сохранённые кнопкой «Сохранить для API» на тестовой странице.
3. Прямой запрос в Мак может передать поле `settings` или любые ключи настроек в теле.

## Скорость ответа

Страница `http://<адрес>:8800/bench` (вкладка «Скорость») или `./bench.sh` в терминале.

Модели запускаются по очереди (на Маке всегда одна), для каждой меряется:

- **Загрузка** — от команды запуска до готовности: веса + прогрев. Если весов нет, сюда входит скачивание.
- **Первый запрос** — первый ответ сразу после загрузки.
- **Ответ на короткие / средние / длинные фразы** — медиана и p90 полного времени от отправки запроса до получения всего аудио.
- **RTF** — время работы нейросети ÷ длительность аудио; меньше 1 — быстрее реального времени.
- **Символов в секунду** и **накладные** — всё, что не нейросеть: нормализация текста, очередь, кодирование, сеть.
- **Память** — пик ОЗУ и памяти ускорителя (MLX/Metal).

Запросы идут прямо в API модели с сохранёнными «настройками для API», то есть так же, как у боевых клиентов. Результаты хранятся в `data/bench/`, выгружаются в CSV, по завершении возвращается модель, работавшая до замера.

```bash
./bench.sh                                   # все установленные модели
./bench.sh silero-v5 omnivoice               # выбранные
SETS=short,medium,long REPEATS=5 ./bench.sh  # все длины фраз, 5 повторов
```

В каждом ответе API есть разбивка времени: заголовок `X-Timing` (нормализация, очередь, нейросеть, первый кусок, кодирование) и `X-Server-Time`. На странице теста она видна при наведении на «синтез» у дубля.

## Логи

- `logs/worker.log` — модель: загрузка, каждый кусок текста, время синтеза.
- `logs/requests.jsonl` — каждый запрос: текст, что прочитано после нормализации, настройки, RTF, ошибки.
- `logs/worker.out` — сырой вывод процесса (трейсбеки, прогресс скачивания).
- `logs/install.log`, `logs/panel.log`.

Всё это видно и скачивается во вкладках /admin.

## Оценки

Каждый дубль сохраняется в `outputs/`. Звёзды, метки проблем и комментарий пишутся рядом. «Сравнение моделей» на странице теста считает среднюю оценку, RTF и частые проблемы; «Скачать CSV» — таблица для Excel.

## Настройки в config.env

`PANEL_PORT`, `TTS_PORT`, `TTS_API_KEY`, `LITELLM_URL`, `LITELLM_MODEL_NAME`, `PANEL_PASSWORD` (пароль на панель), `USE_CAFFEINATE`, `AUTOSTART_LAST`. После изменения: `./stop.sh && ./start.sh`.

## Если что-то не так

- **Модель в статусе «ошибка»** — /admin → Логи → «Модель» или «Вывод процесса»: там трейсбек.
- **«Порт занят»** — кнопка «Освободить порт» в /admin или `lsof -i :8890`.
- **Через LiteLLM 401** — ключ в LiteLLM должен совпадать с `TTS_API_KEY`.
- **Нет звука mp3** — `brew install ffmpeg` (без него ответ всегда wav).
- **Окружение не поставилось** — `./install.sh <id модели>` ещё раз, ошибка в `logs/install.log`.
